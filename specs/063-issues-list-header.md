## 一、页面/功能概述

仓库内 Issue 列表页（Repo Detail → Issues）顶栏改版：标题区改为「灰小字 `owner/name` + 粗体 Issues」
两行（此前第一行只有 owner），搜索从「跳转全域搜索页」改为**当页顶栏内联搜索**（点击搜索图标后标题区
换成输入框，占位「Search Issues」），输入内容对已加载的 Issue 做本地过滤（标题子串或 `#编号`），无匹配时
给空态提示；输入框内右侧在**有文字时**出现灰色 ✕（清空关键词、留在搜索态），**返回键退出搜索**；框右侧的
搜索与新建图标在两种状态下都保持可见；新建图标由 `plus` 换成 `circle-plus`。四个筛选 chip、列表行样式与
分页行为均不变。

---

## 二、整体 UI 结构

1. 顶栏（未搜索态，高 56）：← 返回 + `owner/name`（灰小字，单行省略）+ Issues（粗体）+ 🔍 搜索（蓝）+ ⨁ 新建（蓝，circle-plus）
2. 顶栏（搜索态）：← 返回 + 搜索输入框（占位「Search Issues」，透明底、蓝色光标，占据标题区）+ 框内灰 ✕（**仅当有输入**）+ ⨁ 新建（蓝）——**🔍 在搜索态隐藏**（让位给输入框），⨁ 保持可见
3. 搜索态的退出：← 返回键退出搜索（清空关键词、标题与列表复原）；再按一次才退出本页
4. 筛选 chip 行：漏斗徽标 + All/Label/Author/Assignee（不变，横向滚动）
5. Issue 列表：卡片行样式不变（状态圈 + 标题 + #N + 标签 + 时间 + 💬）；过滤只影响展示集合，分页仍是触底增量加载
6. 空态：搜索词无匹配 → 「No results found」；非搜索场景无数据 → 仍为「No issues」

## 四、核心 GraphQL 片段

无新增查询：搜索为**本地过滤**，数据仍来自 Spec 007 的既有查询（`repository.issues`，带 states/labels/分页）。
服务端全文搜索（`search(type: ISSUE, query: "repo:o/n ...")`）不在本批范围，归属 Spec 046。

## 五、边界 / 不可行项

| 项 | 原因 | ArkCat 处理方式 |
| ---------------------- | -------------------------------------------------- | ------------------------------------------------------------ |
| 本地过滤只覆盖已加载页 | 仓库可能有上万 Issue，首屏仅 25 条 | 输入即过滤已加载集合；滚动触底继续增量加载并纳入过滤（与文件树/Forks 的顶栏搜索一致）。要「服务端全量搜」需另立批次（046） |
| 原「进全域搜索」入口被替换 | 需求明确不跳新页面 | 全域搜索仍从 Home 头部搜索进入，不受影响；该页不再有跳搜索页的入口 |
| 搜索不改变列表排序与筛选 | 搜索只是叠加过滤条件 | 关键词与四个 chip 共同生效；清空关键词即恢复 |
| 编号匹配形式有限 | 只做 `#N` / `N` 精确匹配 | 不做模糊编号匹配（避免「1」命中「123」）；标题仍走子串匹配 |
| Issue 创建入口仍为占位 | 创建页由 Spec 043 承接（未实现） | 保留图标与占位提示，仅换 circle-plus 图标资源 |

## 七、备注

- **为什么用本地过滤**：本页数据是分页 Issue 列表（filter chip 已在本地叠加 Author/Assignee 过滤），
  顶栏内联搜索沿用同一模式，交互即时、无额外请求；服务端全域搜索属 Spec 046 的范围，本批不越界。
- **两行标题口径**：与 Release 详情一致——第一行灰小字放「仓库」身份（`owner/name`），第二行粗体放页面名
  （Issues）。此前第一行只写 owner，信息不完整（同名 owner/name 场景看不出是哪个仓库）。
- **字符串复用**：占位用既有 `page_search_issues`（base「Search Issues」/ zh_CN「搜索议题」，工作区 Issue 列表
  已在用）、空态用 `search_no_results`（No results found / 未找到结果）——本批**不新增字符串资源**，
  也不再使用 `search_cancel`（Forks/文件树仍在用，不受影响）。
- **✕ 与退出路径**：搜索态不用 Cancel 文字按钮，改为**输入框内嵌灰 ✕**（`oct_x_16` + `text_secondary`，有输入才
  显示），与 Home 搜索页（Spec 015）一致；✕ 只清空关键词、**留在搜索态**，退出搜索由**返回键**承担（搜索态下
  先退搜索、再退出本页）。这与 Forks / 文件树的「输入框 + Cancel」写法不同——本页按用户 2026-09-11 要求对齐
  Home 搜索页，若日后要统一两种写法，建议以本页口径为准另开批次。
- **搜索态图标**：进入搜索后 **🔍 隐藏**（用户 2026-09-11 追加要求：输入框出现时它不该还在），⨁ 新建保持可见
  ——即「✕ 不影响更右边其他 icon」中的「其他 icon」指 ⨁。因为 🔍 在搜索态不可点，`enterSearch()` 不再需要
  「已搜索时不清空关键词」的分支，保持最简实现。
- **未动的部分**：筛选 chip 行、Issue 卡片行样式、触底分页、下拉刷新、返回刷新 tick；新建图标的占位提示
  行为也不变（仅换图标资源）。
- **2026-09-11 实测留痕**（freeCodeCamp/freeCodeCamp，Pura 90 Pro）：未搜索态顶栏两行显示
  `freeCodeCamp/freeCodeCamp` 与 Issues，右侧为蓝色 🔍 与蓝色 circle-plus；点 🔍 后 🔍 消失、标题区换成
  占位「Search Issues」的输入框（自动弹键盘），⨁ 仍在；输入 `workshop` 命中 2 条（含一条 closed）、
  输入 `69985` 只余 #69985、输入无匹配串显示「No results found」，有输入时框右端出现灰色 ✕；点 ✕ 关键词
  清空、列表复原且仍在搜索态（✕ 随关键词消失）；按返回键退出搜索、两行标题与 🔍 复原、完整列表回来，
  再按返回才离开本页。
